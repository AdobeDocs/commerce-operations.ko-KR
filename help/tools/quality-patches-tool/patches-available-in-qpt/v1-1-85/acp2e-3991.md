# ACP2E-3991: 클라이언트 IP 주소가 올바르게 확인되지 않음

ACP2E-3991 패치는 클라이언트 IP 주소가 올바르게 확인되지 않고 `sales_order` 테이블의 `remote_ip` 필드에 `127.0.0.1`(으)로 저장되는 문제를 해결합니다. 이 패치는 [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.85가 설치되어 있을 때 사용할 수 있습니다. 패치 ID는 ACP2E-3991입니다. 이 문제는 Adobe Commerce 2.4.9에서 해결되었습니다.

## 영향을 받는 제품 및 버전

**Adobe Commerce 버전에 대한 패치가 만들어졌습니다.**

* Adobe Commerce(모든 배포 방법) 2.4.7-p6, 2.4.8-p5

**Adobe Commerce 버전과 호환:**

* Adobe Commerce(모든 배포 방법) 2.4.7 - 2.4.8-p5

>[!NOTE]
>
>새 [!DNL Quality Patches Tool] 릴리스가 있는 다른 버전에 패치를 적용할 수 있습니다. 패치가 Adobe Commerce 버전과 호환되는지 확인하려면 `magento/quality-patches` 패키지를 최신 버전으로 업데이트하고 [[!DNL Quality Patches Tool]에서 호환성을 확인합니다. 패치 검색 페이지](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). 패치 ID를 검색 키워드로 사용하여 패치를 찾습니다.

## 문제

클라이언트 IP 주소가 올바르게 확인되지 않고 `sales_order` 테이블의 `remote_ip` 필드에 `127.0.0.1`(으)로 저장되는 문제입니다.

<u>재현 단계</u>:

1. Commerce Cloud 인스턴스에서 GraphQL 애플리케이션 서버를 구성합니다.
1. GraphQL을 통해 주문합니다.
1. `sales_order` 테이블의 `remote_ip` 필드에서 만든 순서를 확인합니다.
1. 액세스 로그를 확인합니다.

<u>예상 결과</u>:

요청이 GraphQL을 통해 라우팅되는 경우에도 올바른 IP 주소가 기록됩니다.

<u>실제 결과</u>:

`remote_ip` 필드가 고객의 실제 IP 주소 대신 `127.0.0.1`(으)로 저장됩니다.

개별 패치를 적용하려면 배포 방법에 따라 다음 링크를 사용합니다.

* Adobe Commerce 또는 Magento Open Source 온-프레미스: [!DNL Quality Patches Tool] 가이드의 [[!DNL Quality Patches Tool] > 사용량](/help/tools/quality-patches-tool/usage.md)
